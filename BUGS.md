# p910nd audit — defect register

Target: `p910nd` 0.97-lineage tree (`HiGarfield/p910nd`, same author as
`kenyapcomau/p910nd`). Language level enforced throughout: **ANSI C89**
(`-std=c89 -Wall -Wextra -Wpedantic`, gcc and clang, zero warnings).

Method: full source read-out, upstream `kenyapcomau/p910nd` diff, the Debian
`0.97-1` patch series pulled from `salsa.debian.org/debian/p910nd`, then an
end-to-end harness (`tests/run.sh`) covering build gates, static analysis, unit
tests, functional traffic, sanitizers and valgrind. Every claim below is backed
by either a source line or a test that fails without the fix.

Severity = exploitation/impact × likelihood, not code size.

| ID | Location | Category | Trigger | Severity | Root cause | Fix | Test | Status |

| BUG-008 | `copy_stream_ex()` unidirectional branch | Availability / DoS | Any client that opens a connection and then sends nothing | **High** | The unidirectional loop blocked in `select()` with **no timeout at all** and ignored `-t` completely (that option was only wired into the bidirectional branch). The daemon serves one job at a time, so one silent socket stopped every other host from printing — and connecting needs no authentication. Measured: with `-t 2` the job still ran until the test gave up. | Wake once a second and tear the job down after `-t` idle seconds. The timer is **armed by default** in both directions, with `-t 0` disabling it (operator decision, recorded in UNRESOLVED U9; the earlier revision armed it only when `-t` was given). Closing requires `bytes == 0`, so no byte already accepted can be discarded, and `-t` must be raised for clients that legitimately pause mid-job for longer than 5s. | `uni_idle_timeout_option_closes`, `uni_idle_default_timeout_applies`, `uni_idle_zero_keeps_connection`, `uni_idle_slow_client_survives` (all mutation-verified) | **Fixed** 25d468a, default armed in (this pass) |
| BUG-009 | `copy_stream_ex()` bidirectional grace window (`grace_deadline`) | Latency / regression vs 0.97 | Every bidirectional job on a printer that never reports end-of-stream — i.e. every real parallel or USB printer, whose `read()` returns `EAGAIN` | **Medium** | The post-EOF window that catches a reply arriving just after the host closed its send side was hard-wired to the 5 s compile-time default and ignored `-t`. 0.97 ended the job as soon as the last byte was delivered, so every bidirectional job now paid ~5 s extra (measured 0.2 s of work, 5.2 s wall; under (x)inetd that is a several-fold slowdown of every single job). | The window follows `-t` when a positive value was given and falls back to the compile-time default for `-t 0`, so a job is always bounded. | `bidir_grace_follows_idle_timeout` (mutation-verified: 10.45 s before, ~1.2 s after) | **Fixed** fe2116d |
| BUG-010 | `resolve_user()` / `resolve_group()` | Security / correctness | `-u` or `-g` with a numeric id that does not fit `uid_t`/`gid_t`, e.g. `-u 4294967296` | **Medium** | Any value `strtol()` could parse was cast to `uid_t`. The cast truncates silently, and truncating to 0 means **root**: an operator asking to drop privileges was told `running as uid=0 gid=0` and kept them — the exact outcome `-u` exists to prevent. | Reject a value that does not survive a round trip through the target type, so it is reported as an unknown account | `numeric_id_out_of_range_rejected` (mutation-verified) | **Fixed** 7746574 |
| BUG-012 | `Makefile` libwrap switch | Build / security-relevant misconfiguration | `make USE_LIBWRAP=1` — the spelling the audit brief uses, and the one the source's own macro is named after | **Low** | The Makefile only honoured `USE_WRAP`, while the macro it defines is `-DUSE_LIBWRAP`. | BUG-011 | `Makefile` CFLAGS handling | Build / packaging | Building with a caller-supplied `CFLAGS` that contains a `-W` switch — e.g. Ubuntu's `dpkg-buildflags`, which adds `-Werror=format-security` | **Low** | `override CFLAGS := $(filter-out -W%, $(CFLAGS)) -Wall -Wextra` threw away every `-W*` flag the caller passed, silently disabling exactly the hardening check a distribution build asked for. `install` also set no mode, taking it from the working tree. | Append the project's warnings to the caller's flags; set modes explicitly | `makefile-keeps-user-wflags` gate in `tests/run.sh` | **Fixed** 08c5c32 |

## Verified — no defect found

Each item was examined and, where it can be observed, exercised by a test.

| Area | Conclusion | Evidence |
|---|---|---|
| Ring buffer wrap / off-by-one | **No issue** | All four index cases are handled: empty resets both indices, full → `avail = 0`, unwrapped → `BUFFER_SIZE - endidx`, wrapped → `startidx - endidx`; `writeBuffer()` splits a contiguous chunk at the wrap. `endidx == startidx` ambiguity cannot arise because it implies `bytes == 0` or `bytes == BUFFER_SIZE`, both handled earlier. Exercised at 8191/8192/8193 plus 1 MiB with sha256. |
| `select()` `nfds` / `FD_SETSIZE` overflow | **No issue** | Every `FD_SET`/`FD_ISSET`/`FD_CLR` is guarded by `FD_VALID`/explicit range checks; out-of-range descriptors are duplicated into range by `dup_fd_below_fdsetsize()` before use. `tests/test_dup_fd_leak.c`, `test_prep_writefds.c`. |
| `timeval` reused across `select()` calls | **No issue** | The bidirectional loop re-arms `timeout` every iteration (p910nd.c:1127); the classic 0.96 bug is not present. |
| `ssize_t` / `size_t` and signed mix-ups | **No issue** | All raw `read()`/`write()` results are `ssize_t` and only used after a `> 0`/`< 0` test; never compared as unsigned. |
| `-f` with an over-long path | **No issue** | The argument is used as a pointer, never copied into the fixed-size `lpname[]`, so there is nothing to truncate or overflow. |
| Two-digit port number breaking `LOCKFILE`/`PIDFILE` | **No issue — already fixed here** | `main()` accepts only a *single* digit (`argv[0][1] == '\0'`) and `server()` re-checks `0..9`. Debian patch `40-fix-port-number-bigger-than-9` adds the same guard with `strlen() > 1`; this tree's version is stricter (it also rejects non-digits). |
| `progname` rewrite corrupting the syslog identity | **No issue — hypothesis disproved** | `progname` is set to the *basename* before `strstr("p910n")` runs, so a directory component containing `p910n` is untouched. Confirmed empirically: running `/tmp/p910nd-dir/p910nd` rewrites only the final component (`.../p910nd-dir/p9100d`). |
| Zombie / orphaned children | **No issue** | Jobs are served serially with no per-job `fork()`; the daemon is its own session leader. `no_residual_child_processes` checks `/proc/<pid>/task/<pid>/children`. |
| Descriptor leak across jobs | **No issue** | valgrind over ten sequential jobs leaves no connected socket open and reports `definitely lost: 0`. The still-reachable 4 KiB is glibc's `stdout` buffer from `-d` logging, not daemon state. |
| CPU spin when the printer stalls | **No issue** | Both descriptors are non-blocking and the unidirectional loop blocks in `select()` on writability; `printer_stall_no_cpu_spin` measures < 1 s CPU across 2.5 s of blocked writing. |
| Tail lost on half-close (0.97 "wait until not busy") | **No issue** | `mark_eof_if_drained()` completes the job without waiting for another write opportunity; `half_close_tail_delivered` verifies the last bytes arrive. |
| Printer→network not driven by `select()` (OpenWrt #2444) | **No issue** | Both directions are prepared into the same `readfds`/`writefds` each iteration. |
| Whole-daemon deadlock on a missing printer | *See UNRESOLVED U3* | The retry loop is entered **after** `accept()`, so one client can hold the daemon while the device is absent. This is upstream's documented choice, so it was deliberately left alone. |
| Memory safety overall | **No issue observed** | ASan + UBSan clean over the functional subset; valgrind reports zero errors and zero definite leaks. |
| libwrap (`-DUSE_LIBWRAP`) | **No defect — and now exercised** | An earlier note in this file said `tcpd.h` was absent; that was wrong (I misread `ls`'s exit status) and has been corrected. The build gate compiles and links, the local `hosts_ctl()` declaration is identical to `tcpd.h`'s, and both branches run: no rule serves a byte-exact job, a preloaded deny stub closes the connection with nothing delivered. valgrind shows five rejected connections leave no descriptor. See UNRESOLVED.md U5. |
| `ensure_parent_dir()` with a relative path | **No issue — hypothesis disproved** | The scan starts at `buf + 1`, which looks like it skips the first component. It does not: the loop only ever misses a separator at index 0, i.e. the root of an absolute path, which must not be created anyway. `"rel1/rel2/file"` still creates `rel1` and `rel1/rel2`. Checked while looking for a third-pass defect; no change made. |
| `gcc -fanalyzer` fd-leak at `dup_fd_below_fdsetsize()` | **No issue — false positive** | `-fanalyzer` reports `leak of file descriptor 'dup2(fd, target)'` at the `if (dup2(...) < 0)` branch. On failure `dup2()` creates nothing, so there is no descriptor to leak; the successful path closes the original and returns the duplicate. Every other `-fanalyzer` diagnostic is clean. |
| `clang-tidy` (correctness/security checks) | **No findings** | Run over `p910nd.c` with the project's flags; no diagnostic. |
| (x)inetd path (`one_job()`) | **No defect — and now exercised** | Every functional case used to pin stdin to `/dev/null` (so `is_standalone()` always chose `server()`), leaving `one_job()` unrun. `inetd_one_job_serves_connection` now hands the process an accepted socket as descriptor 0: the job is byte-exact and the process exits 0, which is what inetd needs. |
| `-u`/`-g` ordering | **No issue** | `setgid()` before `setuid()`, `initgroups()` only while privilege is still held; unknown targets are a hard error. Dropping to a *foreign* account still cannot be tested here (needs root) — recorded in UNRESOLVED.md. |
| Portability beyond glibc | **Clean where testable** | `-std=c89` builds warning-free under gcc, clang, musl-gcc and a 32-bit (`-m32`) target; the file also passes a C++98 syntax check. Cross toolchains for arm/mips are in the distro but need root to install, so big-endian targets remain unexercised — recorded, not claimed. |
